# 15.4 - VPC Endpoints

## Transcript

### Qué son
- Conectar a servicios AWS via red privada (sin internet público)
- Escalables y redundantes
- No necesitás IGW, NAT Instance ni NAT Gateway para acceder a servicios AWS

### Dos tipos

#### 1. Gateway Endpoint
- **Solo para S3 y DynamoDB**
- Se crea a nivel de VPC (1 por VPC)
- Actualizar route table con entrada al endpoint
- Aplica a todas las instancias de la subnet con esa route table
- Resolución DNS: mismo hostname público de S3, la route table redirige al endpoint
- **NO se puede extender fuera de la VPC** (no via VPN, DC, TGW, peering)

#### 2. Interface Endpoint
- Para **todos los servicios** (incluidos S3 y DynamoDB)
- Provisiona un ENI (Elastic Network Interface) en tu subnet
- Tiene hostname privado
- Usa Security Groups para seguridad
- Private DNS: hostname público del servicio resuelve al ENI privado
- Requiere: "Enable DNS Hostnames" y "Enable DNS Support" en la VPC
- **SÍ se puede acceder desde Direct Connect y Site-to-Site VPN**

### Troubleshooting
- Verificar DNS resolution en la VPC
- Verificar route tables

### Gateway vs Interface para S3
- Gateway: gratis, route table, no sale de la VPC
- Interface: cuesta, ENI + SG, accesible desde on-prem via DC/VPN

---

## Key Concepts
- Gateway Endpoint = solo S3 y DynamoDB, gratis, route table, NO sale de VPC
- Interface Endpoint = todos los servicios, ENI, SG, SÍ accesible desde on-prem
- Private DNS = hostname público resuelve a IP privada del ENI
