# 14.1 - Cloud Migration Strategies (7R)

## Transcript

Las 7 R de la migración a la nube (basado en blog de AWS):

### 1. Retire (Retirar)
- Apagar servicios que no se necesitan
- Reduce superficie de ataque (más seguridad)
- Ahorro de costes del 10-20%
- Enfoca atención en recursos que sí hay que mantener

### 2. Retain (Retener)
- Decisión de NO migrar a la nube
- Razones: seguridad, compliance de datos, rendimiento, dependencias no resueltas
- No hay valor de negocio para migrar o es demasiado complicado

### 3. Relocate (Reubicar)
- Mover aplicación on-premises a su versión cloud
- Mover instancias EC2 a diferente VPC, cuenta o región
- Ejemplo: VMware on-premises → VMware Cloud on AWS
- Nada cambia en la aplicación

### 4. Rehost (Lift and Shift)
- Migración simple: mover aplicación tal cual a AWS
- Aplica a aplicaciones, bases de datos, datos
- Servidores físicos, virtuales o de otra nube → AWS
- Sin optimización cloud, la app se mantiene igual
- Posible ahorro de hasta 30% en costes
- Herramienta: AWS Application Migration Service

### 5. Replatform (Lift and Reshape)
- No cambia la arquitectura central
- Se aprovechan optimizaciones cloud
- Ejemplo: base de datos on-premises → RDS (backups, HA, resiliencia)
- La aplicación no cambia, pero usa servicios gestionados

### 6. Repurchase (Drop and Shop)
- Cambiar de producto al migrar
- Pasar a plataforma SaaS
- Caro a corto plazo, pero rápido de implementar
- Ejemplos: CRM → Salesforce, RRHH → Workday, CMS → Drupal

### 7. Refactor / Re-architect
- Reimaginar la arquitectura usando características Cloud Native
- Razones: mejorar escalabilidad, rendimiento, seguridad, agilidad
- Dividir monolito en microservicios
- Mayor esfuerzo, pero mayor beneficio
- Ejemplos: arquitectura serverless, uso de S3 para datos

---

## Key Concepts
- 7 estrategias de migración (7R)
- Ordenadas de menor a mayor esfuerzo
- El examen pregunta qué estrategia usar según el escenario
