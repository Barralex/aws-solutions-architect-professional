# 14.10 - VM Migration Services

## Transcript

### 1. Application Discovery Service
- Planificar migración recopilando info de datacenters on-prem
- Trackea: utilización de servidores, mapeo de dependencias

**Dos modos:**
- **Agentless (OVA en VMware):** inventario de VMs, config, CPU/memoria/disco. Cualquier OS.
- **Agent-based:** config, performance, procesos, conexiones de red entre sistemas. Mapea comunicación entre servidores.

**Output:**
- Exportar como CSV
- Ver en AWS Migration Hub
- Consultar con Amazon Athena (datos en S3)
- Visualizar con QuickSight
- Cargar datos adicionales de CMDB

### 2. AWS Application Migration Service (MGN)
- Evolución de CloudEndure Migration + Server Migration Service (SMS)
- Propósito: **Lift and Shift (Rehost)**
- Convierte servidores físicos/virtuales/cloud → EC2 nativo
- Proceso: Agente de replicación → staging (EC2 + EBS) → cutover a producción
- Soporta múltiples plataformas, OS y bases de datos
- Mínimo downtime, costos reducidos

### 3. Elastic Disaster Recovery (DRS)
- Antes: CloudEndure Disaster Recovery
- Similar a MGN pero para **DR, no migración**
- Replicación continua a nivel de bloque
- Failover en minutos a producción completa en AWS
- Failback cuando datacenter vuelve
- Casos: proteger Oracle/MySQL/SQL Server, SAP, ransomware

### Resumen de servicios on-prem → AWS
- **Application Discovery Service:** planificar migración (info + dependencias)
- **Migration Hub:** trackear migración
- **MGN (Application Migration Service):** lift & shift de VMs (reemplaza SMS y CloudEndure Migration)
- **DRS (Elastic Disaster Recovery):** DR de servidores on-prem (reemplaza CloudEndure DR)
- **DMS:** migración de bases de datos

---

## Key Concepts
- Application Discovery: Agentless (VMware OVA) vs Agent-based (mapeo de red)
- MGN = lift & shift (migración), DRS = disaster recovery
- MGN reemplaza CloudEndure Migration + SMS
- DRS reemplaza CloudEndure Disaster Recovery
- Ambos usan replicación continua con agente
