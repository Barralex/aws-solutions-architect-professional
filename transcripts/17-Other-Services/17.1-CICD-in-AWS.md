# 17.1 - CICD in AWS

## Conceptos clave

### CI/CD Basics
- **CI (Continuous Integration):** Devs pushean código frecuentemente → servidor lo buildea y testea automáticamente
- **CD (Continuous Delivery):** Software se puede deployar de forma confiable en cualquier momento → deploys frecuentes y automatizados

### AWS CICD Stack
| Fase | Servicio AWS | Alternativa |
|------|-------------|-------------|
| Code | CodeCommit | GitHub, Bitbucket |
| Build & Test | CodeBuild (sin límite de tiempo) | Jenkins CI |
| Deploy | CodeDeploy / Beanstalk | Spinnaker |
| Orquestación | CodePipeline | - |
| Infra | CloudFormation / Beanstalk | - |

### Arquitectura por branches
- **1 CodePipeline por branch** (dev, prod)
- Cada pipeline tiene su propio CodeBuild, CodeDeploy y entorno Beanstalk
- dev branch → dev pipeline → dev environment
- prod branch → prod pipeline → prod environment
- Merge via Pull Request de dev → prod

### Patrones importantes para el examen
1. **Lambda + CodeCommit:** Trigger en cada commit → escanear credenciales filtradas → desactivar keys IAM + bloquear repo + notificar via SNS
2. **Aprobación manual:** CodePipeline soporta manual approval stages
3. **Unit tests:** CodeCommit → CodeBuild (ejecuta tests) via CodePipeline
4. **Docker:** CodeBuild buildea imagen → push a ECR
5. **CloudFormation deploy:** CodeCommit → CodePipeline deploy stage → despliega templates CF

### GitHub + CodePipeline integración
| Versión | Mecanismo | Eficiencia |
|---------|-----------|------------|
| V1 opción A | Polling periódico | Baja (cada X min/seg) |
| V1 opción B | Webhook HTTP | Alta |
| V2 | CodeStar Source Connection (GitHub App) | Alta (automático) |

## Exam Tips
- CodeBuild > Lambda para builds (sin límite de tiempo)
- 1 pipeline por branch, NO compartir pipelines entre branches
- CodeStar Source Connection = V2 de integración GitHub
- Lambda trigger en CodeCommit = patrón de seguridad (credential scanning)
