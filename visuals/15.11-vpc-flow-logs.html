What are VPC Flow Logs?

Metadata about every network packet entering your interfaces. Not the content — just the envelope.

🌐 VPC Level
All traffic in the entire VPC
📂 Subnet Level
All traffic in one subnet
🔌 ENI Level
Traffic on one specific interface
Also captures managed interfaces: ELB, RDS, ElastiCache, NAT GW, Transit GW...

The Exam Trick — SG vs NACL Troubleshooting

Use the ACTION field (ACCEPT/REJECT) to figure out if the problem is Security Group or NACL.

Remember where they sit:
🌐 Internet
🟡 NACL
(stateless)
🔵 SG
(stateful)
🖥️ EC2
Inbound: REJECT
→ Inbound REJECT
Could be SG or NACL — can't tell
Either one blocked the request
Inbound: ACCEPT + Outbound: REJECT
→ Inbound ACCEPT ✅
↓ request got through
← Outbound REJECT ❌
100% NACL problem
Why? SG is stateful — if inbound was accepted, outbound response is auto-allowed. Only NACL (stateless) would block it.
Outbound: REJECT
← Outbound REJECT
Could be SG or NACL — can't tell
Either one blocked the response
Outbound: ACCEPT + Inbound: REJECT
← Outbound ACCEPT ✅
↓ response got out
→ Inbound REJECT ❌
100% NACL problem
Same logic — SG would auto-allow inbound response
⚠️ Exam golden rule: If one direction is ACCEPT and the other is REJECT → it's ALWAYS a NACL issue. SG is stateful and would never block the return traffic of an accepted connection.

NAT Gateway Gotcha

You see ACCEPT for inbound public IPs to your NAT GW in Flow Logs. Is your NAT GW compromised? No.

🌐 Public IP
(attacker?)
inbound
NACL
ACCEPT ✅
🔀 NAT GW
X
DROPPED
🖥️ EC2
(never reaches)
Flow Logs show ACCEPT because SG/NACL allowed it in.
But NAT Gateway drops unsolicited inbound traffic internally — it never reaches your private instances.
✅ Not a security issue. The ACCEPT in Flow Logs is at the SG/NACL level. NAT GW has its own internal logic that drops unsolicited inbound traffic. Your instances are safe.
