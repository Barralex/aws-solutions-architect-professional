# 17.4 - Kinesis Video Streams + Rekognition

## Key Concepts

### Kinesis Video Streams
- **1 video stream per streaming device** (producers)
- Producers: surveillance cameras, body cams, smartphones, or Kinesis Video Streams Producer Library
- Underlying data stored in S3 — but NO direct access
- **Cannot output stream data directly to S3** → must consume the stream and build custom solution (exam trap!)

### Consumers
- EC2 instances (real-time or batch analysis)
- Kinesis Video Streams Parser Library
- AWS Rekognition (face detection/recognition)

## Architecture: Kinesis Video Streams + Rekognition

```
Video Producers → Kinesis Video Stream → Rekognition (face collection) → Kinesis Data Stream (metadata)
                                                                              │
                                                              ┌───────────────┼───────────────┐
                                                              ▼               ▼               ▼
                                                          EC2 + KCL      Firehose       Analytics
```

## Exam Tips
- **Exam trap:** Cannot write directly from Kinesis Video Stream to S3 — need custom solution via EC2
- Kinesis Video Streams + Rekognition = video analysis + face recognition pattern
- Output of Rekognition goes to Kinesis Data Stream (not Video Stream)
- IoT camera fleet → 1 video stream per camera
